# Story 1.7: Base Layouts & Core UI Components

Status: ready-for-dev

## Story

As a developer,
I want the four application layouts (default, auth, checkout, admin) and core layout components (header, footer, mobile menu) built,
so that every page has consistent navigation, branding, and responsive structure.

## Acceptance Criteria

1. Default layout: header (logo, nav links, search icon, cart icon with count badge, account/login link) + main content slot + footer (brand info, contact, nav links, social links)
2. Auth layout: centered card layout with logo, no header/footer navigation
3. Checkout layout: minimal header (logo + "Back to cart" link), no footer, progress indicator placeholder
4. Admin layout: sidebar navigation (collapsible) + top header bar with admin title and logout
5. Mobile menu: hamburger icon triggers slide-in overlay menu on screens < 768px
6. Cart icon in header shows item count badge from cart store
7. Header shows "Login" link for guests, account dropdown/icon for authenticated users
8. All layouts responsive from 320px to 1440px
9. Footer displays contact phone numbers: +237 670 076 224 / +237 676 328 226
10. Admin sidebar links to all admin sections per architecture doc

## Dev Notes

- Layouts determine which `definePageMeta({ layout: 'xxx' })` each page uses:
  - Storefront pages: `default` (or omit — it's the default)
  - `/auth/*` pages: `auth`
  - `/checkout` page: `checkout`
  - `/admin/*` pages: `admin`
  - `/account/*` pages: `default` (they use the regular storefront layout)
- Use brand color tokens from Tailwind config: `text-brand-primary`, `bg-brand-dark`, etc.
- Header cart badge: `{{ cartStore.itemCount }}` — hidden when 0
- All components must work without real data — use hardcoded placeholders where dynamic content will go later
- Admin sidebar items are hardcoded links — no dynamic menu generation needed
- Mobile breakpoint: use Tailwind's `md:` (768px) as the mobile/desktop threshold
