# Story 1.4: Supabase Project Setup & Database Schema with RLS

Status: ready-for-dev

## Story

As a developer,
I want the complete Supabase database schema created with all tables, indexes, triggers, and Row Level Security policies,
so that the data layer is ready for all application features with proper access control.

## Acceptance Criteria

1. All 14 tables created per architecture doc Section 5.2: `profiles`, `categories`, `products`, `product_variants`, `product_images`, `addresses`, `orders`, `order_items`, `cart_items`, `reviews`, `shipping_zones`, `discount_codes`, `testimonials`, `site_settings`
2. All indexes created per architecture doc (slug, foreign key, search vector, status indexes)
3. Full-text search vector on `products` table (weighted: name=A, description=B)
4. Triggers: `handle_new_user` (auto-create profile), `generate_order_number` (sequential THIA-XXXXXX)
5. Order number sequence: `order_number_seq` starting at 1
6. RLS enabled on ALL tables with policies per architecture doc Section 5.3
7. `is_admin()` helper function created
8. Supabase Storage buckets created: `product-images`, `category-images`, `testimonial-photos`, `site-assets`
9. Storage bucket policies: public read, admin write
10. Seed data: 9 categories, default shipping zones for Cameroon's 10 regions, site settings defaults, admin user
11. All migrations in `supabase/migrations/` directory
12. `supabase/seed.sql` with initial data

## Dev Notes

- All monetary columns use `INT` type — XAF has no decimal subdivisions (ADR-3)
- The `orders` table deliberately stores shipping address fields inline (denormalized) to preserve historical accuracy even if the user later changes their address
- `order_items` stores `product_name` and `variant_label` as snapshots — the product might change after purchase
- `product_variants.price` is the source of truth for pricing; `products` table has no price column
- `search_vector` is a GENERATED ALWAYS column — automatically updates when name/description change
- The `discount_codes` table uses `upper(code)` unique index for case-insensitive lookup
- Storage buckets require Supabase CLI or Dashboard to create — include SQL for policies but bucket creation may need `supabase storage create` command
- Admin user creation: use Supabase Dashboard or CLI to create the auth user, then update profile role
