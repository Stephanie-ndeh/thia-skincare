# Story 6.6 — Performance Optimization

## Status
ready-for-dev

## Description
Achieve Lighthouse scores of Performance 90+, SEO 95+, Accessibility 85+ by optimizing images with `@nuxt/image`, lazy-loading heavy components, verifying SWR cache rules, and adding response caching to key backend routes.

## Acceptance Criteria
- [ ] `@nuxt/image` installed and configured in `nuxt.config.ts` with Supabase as image provider
- [ ] All `<img>` tags in storefront pages replaced with `<NuxtImg>` with explicit `width`, `height`, and `sizes` props
- [ ] Heavy/admin-only components lazy-loaded via `defineAsyncComponent` so they are not bundled into the storefront
- [ ] `routeRules` in `nuxt.config.ts` verified: `swr: 60` for `/`, `/categories/**`, `/products/**`; `ssr: false` (no cache) for `/cart`, `/admin/**`
- [ ] `GET /categories` backend route caches responses for 5 minutes
- [ ] `GET /products/:slug` backend route caches responses for 2 minutes
- [ ] Lighthouse audit run on homepage, a category page, and a product page
- [ ] Lighthouse Performance ≥ 90, SEO ≥ 95, Accessibility ≥ 85 on all three pages
- [ ] Top 3 issues from each Lighthouse audit identified and fixed

## Technical Notes
- `@nuxt/image` Supabase provider: configure `baseURL` to `${SUPABASE_URL}/storage/v1/object/public/`
- `defineAsyncComponent` for admin components: wrap in `ClientOnly` if they use browser-only APIs
- Backend caching: use an in-memory Map with TTL or a lightweight package — do not add Redis for this
- Layout shift (CLS): always pass `width` and `height` to `<NuxtImg>`; use `aspect-ratio` CSS as fallback
- LCP: hero image should NOT be lazy-loaded — use `loading="eager"` on the above-the-fold hero image
- Run Lighthouse via Chrome DevTools → Lighthouse tab in Incognito mode (no extensions)

## Dependencies
- Story 6.1 (SEO & Meta Tags) should be complete before running the SEO portion of the Lighthouse audit
