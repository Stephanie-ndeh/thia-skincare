# Story 5.4 — Review Management

## Status
ready-for-dev

## Description
Implements the admin review moderation page where admins can view, filter, approve, reject, and bulk-action customer product reviews. Backend routes provide filtered review data and individual status updates.

## Acceptance Criteria
- [ ] `/admin/reviews` displays a table: Product, Customer, Rating, Review text (truncated), Date, Status, Actions
- [ ] Table supports filter by status: pending, approved, rejected
- [ ] Pending reviews are visually highlighted (e.g. row background or badge)
- [ ] Each row has an Approve button that sets `status = 'approved'`
- [ ] Each row has a Reject button that sets `status = 'rejected'`
- [ ] Approve/Reject actions call `PATCH /admin/reviews/:id` and update the row optimistically or refresh
- [ ] Rows have checkboxes enabling multi-select
- [ ] A bulk action toolbar appears when one or more rows are selected
- [ ] Bulk toolbar has "Approve selected" and "Reject selected" buttons
- [ ] Bulk actions call `PATCH /admin/reviews/:id` for each selected review (sequentially or in parallel)
- [ ] `GET /admin/reviews` accepts query params: `status`, `page`, `limit` (requireAdmin)
- [ ] Response includes product name and customer name joined from related tables
- [ ] `PATCH /admin/reviews/:id` accepts `{ status: 'approved' | 'rejected' }` (requireAdmin)
- [ ] All routes registered in `app.ts`

## Technical Notes
- File: `apps/frontend/pages/admin/reviews/index.vue`
- `definePageMeta({ layout: 'admin', ssr: false, middleware: 'admin' })`
- Review status type: `'pending' | 'approved' | 'rejected'`
- `GET /admin/reviews` joins `reviews` with `products` (for name) and `profiles` (for customer name)
- Default filter on page load: show `pending` reviews first (or all, with pending highlighted)
- Optimistic UI update: flip the status badge immediately on button click, revert on error
- Pagination recommended but not required for MVP — implement if review volume warrants it

## Dependencies
- Story 5.1 (Admin Dashboard) — admin layout, sidebar, and middleware must exist
