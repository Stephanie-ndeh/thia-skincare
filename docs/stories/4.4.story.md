# Story 4.4 — Wishlist Feature

## Status
ready-for-dev

## Description
Allow authenticated customers to wishlist products. A heart icon on every product card and the product detail page toggles the wishlist state. The dedicated wishlist page displays all saved products. A Pinia store manages wishlist state client-side with backend sync.

- [ ] `POST /wishlist` backend route implemented, requires `authenticate`, toggles product in/out of wishlist
- [ ] `POST /wishlist` returns `{ data: { added: boolean, product_id: string } }`
- [ ] `wishlist_items` migration exists (id, user_id, product_id, created_at); create if missing
- [ ] `WishlistItem` interface added to `packages/shared/types/wishlist.ts`
- [ ] Backend routes registered in `app.ts`

- [ ] `toggleWishlist()` calls `POST /wishlist` and updates local state optimistically

## Technical Notes

**Backend routes: `apps/backend/src/routes/wishlist/index.ts`**
```ts
// GET /wishlist — join wishlist_items with products
// POST /wishlist — upsert/delete toggle
// Both require preHandler: [fastify.authenticate]
// Use request.user.id as user_id filter
```

**Migration** (if `wishlist_items` table doesn't exist):
```sql
create table wishlist_items (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id) on delete cascade not null,
  product_id uuid references products(id) on delete cascade not null,
  created_at timestamptz default now() not null,
  unique (user_id, product_id)
);
alter table wishlist_items enable row level security;
create policy "Users manage own wishlist" on wishlist_items
  for all using (auth.uid() = user_id);
```

**New shared types — `packages/shared/types/wishlist.ts`**:
