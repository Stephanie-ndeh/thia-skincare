# Story 1.2: Nuxt 3 Frontend Scaffold

Status: review

## Story

As a developer,
I want the Nuxt 3 frontend application scaffolded with TypeScript, Tailwind CSS v4, shadcn-vue, Pinia, and @nuxtjs/supabase configured,
so that the frontend is ready for feature development with the correct rendering strategy and design system foundation.

## Acceptance Criteria

1. Nuxt 3 project initialized at `apps/frontend/` with TypeScript enabled and SSR on
2. Tailwind CSS v4 installed and configured with brand token placeholders in `assets/css/main.css`
3. shadcn-vue initialized with default configuration
4. Pinia installed and registered as a Nuxt module
5. @nuxtjs/supabase installed and configured (reads env vars from root)
6. `nuxt.config.ts` includes hybrid rendering route rules per architecture doc Section 3.1
7. Complete directory structure created per architecture doc Section 2 (components/, composables/, layouts/, pages/, stores/, middleware/, plugins/, types/, utils/)
8. `@thia/shared` workspace dependency added to `package.json`
9. `npm run dev` starts the dev server without errors
10. `npm run build` produces a production build without errors

## Dev Notes

- Tailwind CSS v4 uses `@tailwindcss/vite` Vite plugin (NOT `@nuxtjs/tailwindcss`) — the story spec names the wrong module; v4 integration is via the official `@tailwindcss/vite` package
- `@nuxtjs/supabase` reads `NUXT_PUBLIC_SUPABASE_URL` and `NUXT_PUBLIC_SUPABASE_KEY` (not `ANON_KEY`)
- Supabase "missing url/key" warnings during build are expected without real credentials — not errors
- Tailwind sourcemap warning from `@tailwindcss/vite` is a known benign upstream issue
- `components/ui/.gitkeep` must NOT exist — shadcn-nuxt treats all files in that dir as components
- Brand color values are placeholders until client provides the style guide
- `formatXAF` utility per architecture doc Section 11.4

### Project Structure Notes

- All frontend code lives under `apps/frontend/`
- shadcn-vue components go in `components/ui/` (added via `npx shadcn-vue@latest add <component>` per story)
- Custom domain components go in `components/{domain}/`
