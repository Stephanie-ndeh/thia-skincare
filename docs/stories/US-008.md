# Story 1.8: Authentication Pages

Status: ready-for-dev

## Story

As a guest user,
I want to register, log in, reset my password, and confirm my email,
so that I can access my account, track orders, and leave reviews.

## Acceptance Criteria

1. Login page (`/auth/login`): email + password form, "Forgot password?" link, "Create account" link, form validation, error display
2. Register page (`/auth/register`): name, email, phone (Cameroonian format), password form, validation, redirects to confirmation message
3. Forgot password page (`/auth/forgot-password`): email form, sends reset link, shows success message regardless of email existence
4. Reset password page (`/auth/reset-password`): new password + confirm password form, minimum 8 characters
5. Email confirmation page (`/auth/confirm`): handles Supabase email confirmation callback, shows success/error state
6. All forms use shadcn-vue form components (Input, Button, Label)
7. All pages use the `auth` layout
8. Phone number validated in Cameroonian format using `@thia/shared` validator
9. Login redirects to previous page (if any) or `/account` dashboard
10. Protected routes (`/account/*`, `/admin/*`) redirect to `/auth/login` when unauthenticated
11. Nuxt middleware `auth.ts` and `admin.ts` implemented and applied to protected routes

## Dev Notes

- @nuxtjs/supabase handles the OAuth/magic link token exchange automatically when configured with `redirectOptions`
- The `auth` layout (from US-007) provides the centered card container — auth pages just render the form content
- Password reset flow: Supabase sends email with link → user clicks → lands on `/auth/reset-password` → @nuxtjs/supabase exchanges the token → user sets new password
- Error messages should be user-friendly, not raw Supabase errors. Map common errors:
  - `Invalid login credentials` → "Email or password is incorrect"
  - `User already registered` → "An account with this email already exists"
  - `Password should be at least 6 characters` → "Password must be at least 8 characters"
- Middleware runs on both server and client in Nuxt — `useSupabaseUser()` is SSR-compatible
- For the admin middleware, profile data might need to be fetched on server-side. Consider using `useSupabaseClient()` to query profiles table in middleware
