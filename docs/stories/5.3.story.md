# Story 5.3 — Order Management

## Status
review

## Description
Implements the admin order management section: a paginated, filterable order listing page and a full order detail page with status transition controls. Backend routes provide paginated order data and validated status updates.

## Acceptance Criteria
- [x] `/admin/orders` displays a paginated table (Ref, Customer, Date, Items count, Total, Payment status, Order status, Actions)
- [x] Table supports filter by order status: all, pending, confirmed, processing, shipped, delivered, cancelled
- [x] Table supports filter by date range (start date / end date)
- [x] Table supports search by order reference or customer name
- [x] Pagination is 20 orders per page with prev/next controls
- [x] Each row has a View button linking to `/admin/orders/[id]`
- [x] `/admin/orders/[id]` shows full order details: reference, date, customer name and contact
- [x] Order detail shows all line items with product image, name, variant, quantity, and unit price
- [x] Order detail shows the shipping address
- [x] Order detail shows payment method and payment status
- [x] All monetary values are formatted with `formatXAF()`
- [x] Order detail has a dropdown to change order status
- [x] Only valid status transitions (per `ORDER_STATUS_TRANSITIONS` from `@thia/shared`) are shown in the dropdown
- [x] Changing status requires a confirmation step before calling the API
- [x] `GET /admin/orders` returns paginated orders with query param filters (requireAdmin)
- [x] `GET /admin/orders/:id` returns full order detail with items, customer, and payment info (requireAdmin)
- [x] `PATCH /admin/orders/:id/status` validates the transition is allowed before updating (requireAdmin)
- [x] Invalid status transitions return a 422 error with a descriptive message
- [x] All routes registered in `app.ts`

## Technical Notes
- Files:
  - `apps/frontend/pages/admin/orders/index.vue`
  - `apps/frontend/pages/admin/orders/[id].vue`
- All pages: `definePageMeta({ layout: 'admin', ssr: false, middleware: 'admin' })`
- Use `Order`, `OrderItem`, `OrderStatus` types from `@thia/shared`
- Use `ORDER_STATUS_TRANSITIONS` from `@thia/shared` to build the allowed-transitions dropdown and to validate on the backend
- `GET /admin/orders` query params: `status`, `date_from`, `date_to`, `search`, `page`, `limit` (default 20)
- Response envelope follows the standard `{ data: Order[], meta: PaginationMeta }` shape
- `PATCH /admin/orders/:id/status` body: `{ status: OrderStatus }`
- Backend must look up the current order status, check `ORDER_STATUS_TRANSITIONS[currentStatus].includes(newStatus)`, and reject if not allowed
- Status badges should use the same color mapping as the storefront

## Dependencies
- Story 5.1 (Admin Dashboard) — admin layout, sidebar, and middleware must exist
- `ORDER_STATUS_TRANSITIONS` must be exported from `@thia/shared`
