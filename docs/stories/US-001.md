# Story 1.1: Monorepo Initialization & Git Setup

Status: review

## Story

As a developer,
I want the monorepo scaffolded with npm workspaces, shared TypeScript config, and Git initialized,
so that all project packages share dependencies and configuration from day one.

## Acceptance Criteria

1. Root `package.json` declares npm workspaces: `apps/frontend`, `apps/backend`, `packages/shared`
2. `tsconfig.base.json` at root with shared compiler options (strict, ES2022, module resolution)
3. `packages/shared` package initialized with its own `package.json` (name: `@thia/shared`) and `tsconfig.json` extending base
4. `.gitignore` covers: `node_modules/`, `.nuxt/`, `.output/`, `dist/`, `.env`, `.env.local`, `.supabase/`
5. `.env.example` at root with all required environment variables documented (no real values)
6. `README.md` with project name and basic setup instructions
7. `npm install` from root succeeds without errors
8. TypeScript compilation (`tsc --noEmit`) passes in shared package

## Dev Notes

- Use npm workspaces (NOT pnpm, NOT yarn, NOT Turborepo) per ADR-7 in architecture doc
- Node.js 20+ required for native fetch and modern ESM support
- The shared package will be populated with types, constants, and validators in later stories
- Do NOT install dependencies for frontend/backend yet — those are separate stories
