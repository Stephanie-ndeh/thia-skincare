# Story 5.6 — Discount Codes Management

## Status
ready-for-dev

## Description
Implements the admin discount codes management page. Admins can view all discount codes, create new ones, edit existing ones, toggle active status inline, see usage progress, and delete codes. Backend routes handle full CRUD for discount codes.

## Acceptance Criteria
- [ ] `/admin/discounts` displays a table: Code, Type, Value, Min Order, Usage count / Limit, Expires, Active, Actions
- [ ] Usage column shows a progress indicator (e.g. "3 / 10" or a progress bar) based on `usage_count` vs `usage_limit`
- [ ] Each row has an inline toggle for `is_active` that calls `PUT /admin/discount-codes/:id` immediately
- [ ] "Create" button opens a form (modal or inline) with fields: code, type (percentage / fixed), value, minimum_order, usage_limit, starts_at, expires_at
- [ ] Code input is uppercase-enforced (or auto-upcased on submit)
- [ ] Type dropdown has two options: `percentage` and `fixed`
- [ ] Editing a code opens the same form pre-populated with current values
- [ ] Delete button shows a confirmation before calling `DELETE /admin/discount-codes/:id`
- [ ] Expired codes are visually distinguished (e.g. muted text or "Expired" badge)
- [ ] `GET /admin/discount-codes` returns all codes (requireAdmin)
- [ ] `POST /admin/discount-codes` creates a new code (requireAdmin)
- [ ] `PUT /admin/discount-codes/:id` updates any code fields (requireAdmin)
- [ ] `DELETE /admin/discount-codes/:id` hard-deletes the code (requireAdmin)
- [ ] All routes registered in `app.ts`

## Technical Notes
- File: `apps/frontend/pages/admin/discounts/index.vue`
- `definePageMeta({ layout: 'admin', ssr: false, middleware: 'admin' })`
- Discount code record shape:
  ```ts
  {
    id: string
    code: string
    type: 'percentage' | 'fixed'
    value: number
    minimum_order: number | null
    usage_count: number
    usage_limit: number | null
    starts_at: string | null
    expires_at: string | null
    is_active: boolean
    created_at: string
  }
  ```
- `value` for `percentage` type is stored as a plain number (e.g. `15` = 15%); for `fixed` type it is XAF amount
- Display `value` accordingly: append `%` for percentage, use `formatXAF()` for fixed
- A code is considered expired when `expires_at` is in the past
- `usage_limit: null` means unlimited; display as "∞" in the table
- Backend should validate that `value > 0` and, for percentage type, `value <= 100`
