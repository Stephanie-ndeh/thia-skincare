# Story 1.5: Shared Package — Types, Constants & Validators

Status: ready-for-dev

## Story

As a developer,
I want the `@thia/shared` package populated with TypeScript types, Cameroon constants, and validation utilities,
so that frontend and backend share a single source of truth for data shapes, enums, and business rules.

## Acceptance Criteria

1. All TypeScript types defined per architecture doc `packages/shared/types/`: Product, ProductVariant, Category, Order, OrderItem, OrderStatus, User/Profile, Address, CartItem, Review, Payment, ShippingZone, DiscountCode, Testimonial, SiteSettings, API response envelope
2. Constants defined: Cameroon's 10 regions with their cities, order status enum with valid transitions, NotchPay payment channel codes
3. Validators defined: Cameroonian phone number validation, XAF currency formatting/parsing
4. All exports accessible via `@thia/shared` import
5. TypeScript compilation passes with zero errors
6. Both `apps/frontend` and `apps/backend` can import from `@thia/shared`

## Dev Notes

- All types should be interfaces (not classes) for serialization compatibility
- Price/cost fields are always `number` representing XAF integers — never floats
- Phone validation regex: `/^(\+?237)?6[0-9]{8}$/`
- Order status transitions (architecture doc Section 11.5):
  ```
  pending → confirmed → processing → shipped → delivered
  pending → cancelled
  confirmed → cancelled
  processing → cancelled
  ```
- Keep types lean — no methods, no business logic beyond validation
