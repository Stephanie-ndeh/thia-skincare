# Story 6.3 — Mobile Optimization

## Status
ready-for-dev

## Description
Perfect experience on all mobile screen sizes (320px–768px). Every key page is tested and fixed for layout, interaction, and usability on small screens, with all interactive elements meeting minimum touch target and font size requirements.

## Acceptance Criteria
- [ ] Homepage hero is readable on 320px screens; category grid is 2 columns on mobile; product grid is 2 columns on mobile; announcement strip scrolls smoothly
- [ ] Mobile menu opens and closes correctly; cart icon shows badge count; search works on mobile
- [ ] Product detail image gallery is swipeable on mobile; variant pills wrap correctly; Add to Cart button is full width on mobile; tabs scroll horizontally if needed
- [ ] Cart page is single column on mobile (items stacked above summary); CartSummary is full width
- [ ] Checkout form is single column on mobile; inputs scroll into view when keyboard opens; phone input has `inputmode="tel"`
- [ ] Account sidebar becomes a horizontal tab bar on mobile; data tables scroll horizontally
- [ ] Admin tables scroll horizontally on mobile; admin forms stack vertically on mobile
- [ ] All interactive elements meet minimum 44×44px touch target
- [ ] All form inputs have `font-size` minimum 16px to prevent iOS auto-zoom

## Technical Notes
- Use Tailwind responsive prefixes (`sm:`, `md:`) — do not write media query CSS from scratch
- Horizontal scroll on tables: wrap `<table>` in a `<div class="overflow-x-auto">` container
- Account sidebar → tab bar: use `hidden md:block` / `block md:hidden` pattern
- iOS zoom on inputs is triggered by `font-size < 16px` — audit all `<input>`, `<select>`, `<textarea>` elements
- Touch targets: use `min-h-[44px] min-w-[44px]` on small icon buttons
- Admin panel is desktop-first but must remain usable on tablet (768px+)
- Test with Chrome DevTools device emulation at 375px (iPhone SE) and 390px (iPhone 14)

## Dependencies
None — this story can be started independently.

## Definition of Done
- [ ] All acceptance criteria met
- [ ] Zero TypeScript errors
- [ ] No `any` types
- [ ] Reviewed by QA
